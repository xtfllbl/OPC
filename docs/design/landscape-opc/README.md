# OPC_PAD 横屏顾客支付原型

状态：按用户第二轮视觉与流程纠正重做。以下为当前决策，替代首版“四方式同价、顶底栏、内嵌演示面板及任意视口铺满”方案。

## 用户确定的范围

- 独立项目 `OPC_PAD/`，仅交互原型；顾客使用横屏设备，收银员操作独立收银机。
- 支持 1600×720 与 1920×1200，支付区和广告/商品区各半，整块左右对换。
- 待机展示广告；交易到来，广告切换为商品明细，保留到结果结束。
- 顾客主屏无顶栏、底栏、时钟、状态栏、演示/设置入口、自创副标题。
- 收银机下发和设置集中于独立 `launcher.html`；下发时在独立标签页打开 `index.html`，复用顾客页并保留 launcher。
- 视觉与流程基于 OPC_ATTD 实际页面，约束写入 `OPC_PAD/AGENTS.md` 并由根 AGENTS.md 指向。
- CASH、DEBIT SALE、CREDIT SALE、WALLET 均在方式选择卡显示各自应付金额。
- 恢复小费，并在支付方式选择时体现 Dual Pricing。
- 现金由收银员确认；钱包独立纯模拟，服务商未定，不出现银行卡提示。

## 金额决策

- 默认开启小费及双价，两者在收银机设置中可关闭。
- Cash base = 示例订单应付金额 + 确认小费。
- CASH/WALLET 默认 Cash base；DEBIT/CREDIT 默认 round(Cash base × 1.04)。
- DEBIT 与 WALLET 的独立定价不是原项目事实；当前映射是用户授权下的原型决策。
- 示例：商品应付 $33.17，20% 小费 $6.63，现金/钱包 $39.80，银行卡 $41.39。
- 两组价格仅在支付方式卡片展示；商品明细仅显示一个 Total，选择前为基础金额，选择后为所选方式金额，与结果一致。
- 示例 USD、商品优惠和 8% 税率仅供演示。

## 流程

1. 收银机下发订单 → 小费（启用时）→ 支付方式。
2. 小费比例/自定义 → 总额确认 → 方式选择；No Tip 直接进入方式选择。
3. 银行卡呈卡等待 5 秒自动返回模拟结果 → 信用卡签名（启用时）→ Approved；呈卡页无 Tap/Insert、Change Payment Method 及移卡确认按钮。
4. WALLET → Pay → Processing → Approved / Declined。
5. CASH → 等待收银员 → 独立收银机页确认收款 → Approved。
6. Approved 暂时移除整个 CUSTOMER COPY 模块及 Email、邮件表单，仅保留交易摘要、支付凭证与沉底 OK(10s)。设备没有打印机。
7. Declined 保留商品明细，按 ATTD 失败结构显示，红色 OK(10s)。处理中禁止重复选择。
8. 收银员可以取消尚未批准的交易；取消沿用 ATTD 结果结构，蓝色圆圈叉号、Transaction Cancelled 和全宽 OK(10s)。成功、失败、取消均每秒递减，点击 OK 或 10 秒结束清除当前交易并回广告待机。批准后的签名不允许当未支付交易取消。
9. 广告仅待机时每 6 秒切换；交易阶段停止展示。

## 固定画布与缩放

- `index.html` 使用选定尺寸的固定设计画布，不用浏览器窗口替代设备尺寸。
- 1600×720 和 1920×1200 各自指定字号、按钮和表格密度。支付选择去掉商户图标；Change Tip 为全宽按钮，分别至少 64/88px 高。
- 浏览器预览在深色背景上居中，保留 32px 周边空间及设备边框，等比缩小，最大为 1:1。
- 原生验证视口为 1664×784、1984×1264，分别容纳 1:1 的两种设备画布；另验证 1280×800 浏览器缩放。
- 商品列表独立滚动，汇总始终可见。两个模块使用独立背景和边框，中间保留明确间隔。
- 成功、失败、取消页的 OK 均固定在各自支付内容区底部；成功页暂不展示 CUSTOMER COPY 模块。签名页 Clear / Confirm 同样沉底，签名画布扩展占用其上方剩余高度，两种设备尺寸均保留完整可操作区域。
- 设置保存于浏览器；交易中左右布局延迟到空闲生效，其他设置对下一笔交易生效。
