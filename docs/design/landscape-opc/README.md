# 横屏 OPC 需求访谈

状态：两轮问题已回答，等待用户确认最终共同理解后进入原型实现。

## 已明确的要求

- 新建一个 OPC 项目，沿用现有界面的设计风格。
- 横屏设备分辨率：1600 × 720、1920 × 1200。
- 默认左侧为支付区，右侧为广告区，广告内容为轮播图。
- 支付区与广告区支持自定义左右对换。
- 收银机下发交易时，可以查看商品明细，并选择支付方式。
- 支付方式名称：CASH、DEBIT SALE、CREDIT SALE、WALLET。
- 本次仅做交互原型。
- 横屏面向顾客；收银员操作独立收银机。
- 交易到来后，广告区停止展示广告，切换为商品明细；支付区展示支付操作。
- 店员在设置中选择支付区在左或在右，配置保存后持续生效，在空闲时应用。
- 用户倾向各占一半，并授权根据两个目标分辨率评估后选择合适比例。

## 设计决策树

- 交付范围：已确定为原型，不需要真实收银机和支付集成。
- 操作角色：已确定为顾客操作，收银员使用独立收银机。
  - CASH：顾客选现金后等待收银员收款，由模拟收银机操作确认成功。
  - WALLET：独立的纯模拟钱包支付流程，服务商未确定；不显示刷卡、插卡或碰触提示。此前二维码建议不作为已确认要求。
  - 切换方式与取消：未开始支付处理前允许返回选择；处理中禁止重复选择；整笔交易由收银员取消。
  - 价格：四种方式同价，不继承旧原型的双价规则。
- 交易期间布局：已确定商品明细替换广告。
  - 明细：名称、数量、单价、行金额，无商品图片；列表独立滚动，小计、优惠、税额、应付总额固定可见。
  - 成功：成功提示和商品明细保留 5 秒，再回到空闲广告状态；不展示电子小票二维码。
  - 失败：保留商品明细，允许重试或更换支付方式。
- 双分辨率布局：用户授权设计评估，采用 50:50，待原型渲染验证。
- 左右对换：已确定店员配置、保存并在空闲时生效。
- 视觉参考：沿用现有 OPC_ATTD 蓝白、Inter、圆角卡片与大金额视觉语言。
- 空闲支付区内容：商户标识、欢迎语、等待收银员发起交易的提示；收到交易后才显示金额及支付选项。
- 界面语言：沿用现有英文风格。

## 状态与展示

| 状态 | 支付区 | 广告区 / 商品区 |
| --- | --- | --- |
| 空闲 | 商户标识、欢迎语、等待交易提示 | 广告轮播 |
| 收到交易 | 应付金额、四种支付方式 | 商品明细及固定汇总 |
| 等待现金收款 | 请向收银员支付现金 | 保留商品明细 |
| 银行卡支付 | 对应 DEBIT SALE / CREDIT SALE 的模拟银行卡流程 | 保留商品明细 |
| 钱包支付 | 独立的钱包模拟状态，不绑定服务商 | 保留商品明细 |
| 处理中 | 处理状态，禁止重复选择支付方式 | 保留商品明细 |
| 成功 | 成功提示，5 秒后回到空闲 | 保留明细 5 秒，再恢复广告 |
| 失败 | 失败提示，可重试或更换方式 | 保留商品明细 |
| 收银员取消 | 同步显示交易取消结果 | 不显示已完成收款 |

## 原型验收范围

- 在 1600 × 720 与 1920 × 1200 下分别检查完整界面、按钮可用性、明细滚动与固定汇总。
- 验证默认布局与左右对换、配置保存及空闲生效。
- 验证模拟下发交易、四种方式、返回选择、处理中防重复选择、现金收款确认、成功、失败、收银员取消和广告恢复。
- WALLET 不包含任何银行卡操作提示；不因未选服务商而引入真实接口。
- 不将原型操作结果作为实际支付或收银机集成证据。

## 双分辨率布局评估

以下为尺寸推导，尚非浏览器实测。50:50 时，两区在 1600 × 720 设备上各宽 800px，在 1920 × 1200 设备上各宽 960px（均未扣除分隔线和内边距）。支付方式可以采用 2 × 2 排列，商品区保留更充足的商品名称与金额列空间。

若采用支付 60%、明细 40%，商品区分别只有 640px、768px；当前商品与支付已分区，不需要支付区占更大宽度。决定先采用用户倾向的 50:50，720px 高度下紧凑排布、1200px 高度下增加留白及可见商品行数，明细列表独立滚动。最终需在两种目标尺寸下验证。
